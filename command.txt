# TopoFocus 真机实验原始命令清单
#
# 使用方法：
#   打开本文件，一次只复制并运行当前需要的一个命令区块。
#   不要把整个 command.txt 当脚本一次性执行。
#
# 支持的语义目标：
#   chair / bed / plant / toilet / tv / sofa
#
# 当前准备实验：
#   goal       = plant
#   scene      = scene02-plant
#   formal runs = scene02-plant-run01 ... scene02-plant-run05
#
# Scene 01 的 current session 只作为归档，不可用于 Scene 02。Scene 02
# 正式运动前必须在最终摆位上完成本文件第 1 节的新标定与严格无运动 debug。
#
# 当前 Yunji 命令路径：
#   Odin 在线深度/点云 -> TinyNav 在线地图/A*/局部规划/控制
#   -> /focus_guarded_cmd_vel -> WATER /api/joy_control
# 不需要加载 WATER 旧地图，也不调用 accessible_point_query/make_plan/api/move。
#
# 上下电后先按这三类判断：
#   A. 只给 Go2/WATER 底盘下电，Jetson/Odin/SLAM 没重启：
#      仅在整台机器人和相机物理位置完全未变时，不需要标定或重复 debug；
#      底盘重新站立后直接运行第 3/4 节。把整台机器人移到充电位不属于 A。
#   B. Hub 本机、Foxglove 或 SSH 重启，但两端 tracking 进程没重启：
#      同样直接运行 live；一键脚本会恢复 Hub/隧道外的本机组件。
#   C. WSJ perception/SLAM 或 Yunji Odin driver 重启，或者相机/机器人被挪动：
#      旧 session 不可直接 live。脚本会在发布 GOAL 前显示
#      TRACKING_EPOCH_CHANGED 并停止。机器人确实移动时执行第 1 节；仅 tracking
#      重启且机器人始终未动时可做静止重锚，不要伪造旧 session。
#
# 同一 session 的第 2～5 次 live 默认走快速复用：
#   不重复完整 debug，不重建匹配的地图/Foxglove；两端并行启动。
#   每次结束只移除底盘命令链，保留相机、TinyNav、地图和预览继续运行。


# ======================================================================
# 1. 新物理摆位：一次完成共享标定、fresh map、Foxglove 和严格无运动 debug
# ======================================================================
#
# 两台机器人必须保持静止。脚本会先启动一个 Foxglove preview：
#   若既有 WSJ/Yunji SSH tmux pane 已断线，会原位重连并先验证远端 shell；
#   若 WSJ 控制节点残留未具名 DDS 发布端，会闭锁式清理后自动恢复；
#   第一次提示：确认两边都完整看到 7 x 10 圆点板，直接按 Enter；
#   脚本完成第一次拟合后，提示只移动标定板；
#   第二次提示：再次确认两边完整看到板，直接按 Enter；
#   随后自动完成 holdout、部署、fresh map 和无运动 debug。
# 每个新摆位必须使用新的、全小写 session ID。下面自动生成一次性 ID，
# 避免重复使用旧目录；同一轮后续 live 仍统一使用 --session-file current。
#
# 成功标志：
#   DEBUG_FULLSTACK_READY
#   两台机器人各输出 focus-tinynav-data-plane-verification-v1 / passed=true
#   hub/runtime/sessions/current.json 已生成
#
cd /home/asus/Research/focus_realworld_workspace
SESSION_ID="scene02-plant-$(date +%Y%m%d-%H%M%S)"
bash hub/scripts/calibrate_realworld_session.sh \
  --session-id "$SESSION_ID" \
  --operator-confirmation OPERATOR_PRESENT_AND_BOARD_ONLY \
  --goal-category plant


# ======================================================================
# 2. 可选：强制重新检查全栈，不允许机器人运动
# ======================================================================
#
# 只在改过代码、怀疑数据链异常或需要重新生成严格 debug 证据时运行。
# 单独给底盘下电/上电不要运行这一节；直接运行 live 即可。
# 一键脚本仍会检查 current session 的 Git 和 tracking epoch。
#
cd /home/asus/Research/focus_realworld_workspace
bash hub/scripts/realworld_oneclick.sh \
  --session-file current \
  --mode debug \
  --scene-id debug-plant \
  --goal-category plant

# ======================================================================
# 3. 正式真机实验：一次 supervised live episode
# ======================================================================
#
# 必须先看到同一 Git/current session 的 DEBUG_FULLSTACK_READY。
# 两台机器人必须已经上电、站立、周围无障碍，并且操作者在旁边。
# Ctrl-C 会触发底层 fail-closed cleanup。
# 发布前会保留原始双机 VLM candidate，先检查各前沿到达盘内是否存在
# 满足机体净空的已知自由落脚点，再运行 0.9 m 路线冲突门控：
# 不安全前沿只 HOLD 对应机器人；路线冲突时一台 GOAL、另一台 HOLD；
# 共享位姿都不可用时两台 HOLD。
#
# 每次实验必须使用新的 episode ID。下面是 scene02 的第一次：
# 默认自动走快速复用。看到 FAST_LIVE_REUSE_READY 表示没有重复冷启动；
# 若 warm core 不完整，脚本会自动显示 FULL_DEBUG_RUNTIME_RECOVERY。
# 启动阶段会逐项输出 ONECLICK_TIMING；双机版本校验、GLM/预览和可安全
# 并行的只读恢复不会再串行等待。旧提交的 sender 只重载一次，后续保持热态。
#
cd /home/asus/Research/focus_realworld_workspace
bash hub/scripts/realworld_oneclick.sh \
  --session-file current \
  --mode live \
  --scene-id scene02-plant \
  --episode-id scene02-plant-run01 \
  --goal-category plant \
  --operator-confirmation OPERATOR_PRESENT_AND_ROBOTS_CLEAR
